# Control Flow

## Overview

**Control Flow** refers to the order in which a program's instructions are executed. By default, a computer runs code **line by line, from top to bottom** — this is called **sequential flow**. But real programs almost always need to make decisions: "do this if a condition is true, otherwise do something else." Control flow statements are exactly what let a program *choose* between different paths, instead of blindly running every line in order.

Think back to our flowchart topic — remember the diamond (decision) shape? Control flow statements like `if`, `else`, and `switch` are the actual code versions of that diamond shape. They're what let your program "branch" — taking one path or another — based on whatever condition or boolean value you give it.

Without control flow, every program would behave identically every single time, regardless of user input or circumstances. Control flow is what makes a program *responsive* — able to react differently to different situations, which is really the whole point of writing software in the first place.

## Key Concepts

- **Sequential Flow** — The default behavior: instructions run one after another, top to bottom, unless something changes that order.
- **Conditional Statement** — Code that only runs if a certain condition is true, using `if`.
- **Branching** — When a program's execution path splits into two or more possible directions, based on a condition.
- **`if` Statement** — Runs a block of code only if a condition evaluates to true.
- **`else` Statement** — Runs a block of code when the `if` condition was false.
- **`else if`** — Lets you check multiple different conditions in sequence, one after another.
- **Nested `if`** — An `if` statement placed inside another `if` statement, for checking more specific conditions.
- **Ternary Operator (`? :`)** — A compact, one-line shorthand for a simple `if/else` that produces a value.
- **`switch` Statement** — An alternative to many `else if` checks, useful when comparing one variable against several exact possible values.
- **`break`** — Used inside a `switch` to stop checking further cases once a match is found.
- **`goto`** — A rarely-used statement that jumps execution directly to a labeled point in the code, generally avoided in modern programming.

## Example — if, else if, else, Step by Step

```c
#include <stdio.h>

int main() {
    int score = 82;

    if (score >= 90) {
        printf("Grade A\n");
    } else if (score >= 75) {
        printf("Grade B\n");
    } else if (score >= 50) {
        printf("Grade C\n");
    } else {
        printf("Grade F\n");
    }

    return 0;
}
```

## Combining Conditions with && and || Inside if

Real-world decisions often depend on more than one thing at once:

```c
#include <stdio.h>

int main() {
    int age = 25;
    int hasLicense = 1;
    int hasInsurance = 0;

    if (age >= 18 && hasLicense && hasInsurance) {
        printf("You can legally drive.\n");
    } else if (age >= 18 && hasLicense && !hasInsurance) {
        printf("Get insurance before driving.\n");
    } else {
        printf("You cannot drive yet.\n");
    }

    return 0;
}
```

**Output:**
```text
Get insurance before driving.
```

Here, three separate boolean conditions are combined with `&&` to check that **all** requirements are met, and `!hasInsurance` checks that insurance is specifically missing. This is where control flow and boolean logic (from the previous topic) work directly together.

## Nested if — Decisions Inside Decisions

```c
#include <stdio.h>

int main() {
    int age = 20;
    int hasTicket = 1;

    if (age >= 18) {
        if (hasTicket) {
            printf("Entry allowed\n");
        } else {
            printf("Buy a ticket first\n");
        }
    } else {
        printf("Must be 18 or older\n");
    }

    return 0;
}
```

Here, the inner `if (hasTicket)` only gets checked **at all** if the outer condition (`age >= 18`) was already true — this is called **nesting**.

**Output:**
```text
Entry allowed
```

## ⚠️ The Dangling Else Problem — A Common Beginner Trap

```c
int x = 5, y = 10;

if (x > 0)
    if (y > 20)
        printf("Both conditions true\n");
    else
        printf("This else belongs to the INNER if, not the outer one!\n");
```

This is a classic gotcha: without curly braces `{ }`, an `else` always attaches to the **nearest unmatched `if`** — which is `if (y > 20)`, not `if (x > 0)`.

**Best practice:** Always use curly braces `{ }` around `if`/`else` blocks, even for single-line statements:

```c
if (x > 0) {
    if (y > 20) {
        printf("Both conditions true\n");
    } else {
        printf("Now it's unambiguous which if this belongs to\n");
    }
}
```

## ⚠️ The Accidental Semicolon Bug

```c
#include <stdio.h>

int main() {
    int x = 5;

    if (x > 10);  // DANGER: notice the semicolon here!
    {
        printf("This ALWAYS prints, regardless of x!\n");
    }

    return 0;
}
```

**Output:**
```text
This ALWAYS prints, regardless of x!
```

This is a sneaky, silent bug: the semicolon right after `if (x > 10)` actually ends the `if` statement immediately, with an **empty statement** as its body. The `{ }` block below is now just a regular, independent block of code that always runs — completely disconnected from the `if` condition. C won't warn you about this, since it's technically valid syntax, which makes it one of the most frustrating bugs for beginners to spot. Always double-check that there's no stray semicolon right after an `if (...)` or `while (...)` condition.

## The Ternary Operator — A Compact if/else Shortcut

```c
#include <stdio.h>

int main() {
    int age = 16;

    // Long way, using if/else:
    const char *status1;
    if (age >= 18) {
        status1 = "Adult";
    } else {
        status1 = "Minor";
    }

    // Short way, using the ternary operator:
    const char *status2 = (age >= 18) ? "Adult" : "Minor";

    printf("%s\n", status1);
    printf("%s\n", status2);

    return 0;
}
```

Both `status1` and `status2` produce the exact same result: `"Minor"`. The ternary operator `condition ? valueIfTrue : valueIfFalse` is best used for **simple** either/or decisions that produce a value — for more complex logic with multiple statements, a regular `if/else` is usually clearer and easier to read.

## The switch Statement — A Cleaner Alternative for Multiple Exact Matches

```c
    int day = 3;

    switch (day) {
        case 1:
            printf("Monday\n");
            break;
        case 2:
            printf("Tuesday\n");
            break;
        case 3:
            printf("Wednesday\n");
            break;
        case 4:
            printf("Thursday\n");
            break;
        case 5:
            printf("Friday\n");
            break;

            printf("Weekend\n");
    }

    return 0;
}
```

## switch with char — Not Just Numbers

`switch` isn't limited to integers — it also works cleanly with single characters:

```c
#include <stdio.h>

int main() {
    char grade = 'B';

    switch (grade) {
        case 'A':
            printf("Excellent!\n");
            break;
        case 'B':
            printf("Good job!\n");
            break;
        case 'C':
            printf("You can do better.\n");
            break;
        default:
            printf("Invalid grade\n");
    }

    return 0;
}
```

**Output:**
```text
Good job!
```

This works because in C, a `char` is really just stored as a small integer internally (its ASCII value), so `switch` can compare characters exactly the same way it compares numbers.

## ⚠️ Forgetting break — "Fall-Through" Behavior

```c
int day = 2;

switch (day) {
    case 1:
        printf("Monday\n");
    case 2:
        printf("Tuesday\n");
    case 3:
        printf("Wednesday\n");
        break;
    default:
        printf("Other day\n");
}
```

**Output:**
```text
Tuesday
Wednesday
```

Notice this printed **two lines**, not one! Since `case 2` had no `break;`, C doesn't stop there — it keeps "falling through" and running every case below it too, until it finally hits a `break;` inside `case 3`. This is called **fall-through**, and forgetting a `break` is one of the most common `switch` mistakes beginners make.

## if/else vs switch — When to Use Which

| Use `if / else if / else` when... | Use `switch` when... |
|---|---|
| Checking ranges (`score >= 90`) | Checking exact values only (`day == 3`) |
| Checking multiple different variables | Checking one single variable repeatedly |
| Using complex conditions (`&&`, `\|\|`) | Comparing against a fixed list of possible values |
| Conditions involve floats or strings | Conditions involve integers or characters (in C) |

## goto — Mentioned for Completeness (Best Avoided)

```c
#include <stdio.h>

int main() {
    int x = 5;

    if (x == 5) {
        goto skip;
    }

    printf("This will be skipped\n");

    skip:
        printf("Jumped here directly\n");

    return 0;
}
```

**Output:**

```text
Jumped here directly
```

`goto` jumps execution directly to a labeled line elsewhere in the code, bypassing normal control flow entirely. While it technically exists in C, it's **almost universally discouraged** in modern programming, because overusing it makes code extremely hard to read and follow — famously nicknamed "spaghetti code," since the program's execution path can jump around unpredictably instead of following clear, structured branches like `if`/`else` or loops. It's included here only so you recognize it if you ever encounter it in older code; you generally won't need to use it yourself.
