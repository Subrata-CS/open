# Algorithm

## Overview

An **Algorithm** is a clear, step-by-step set of instructions to solve a specific problem or complete a task. It's not tied to any particular programming language — it's the *thinking* and *planning* that happens before you write any code at all.

Think about how you'd explain to a friend how to find the largest of three numbers written on paper. You wouldn't just say "find the biggest" — you'd walk them through exact steps: "Look at the first two numbers, keep whichever is bigger. Now compare that with the third number, and keep whichever is bigger this time. That's your answer." This exact sequence of steps — clear, ordered, and unambiguous — is an algorithm.

The important thing to understand is: **the same algorithm can be written in any programming language** — C, Python, JavaScript — because an algorithm is about the *logic*, not the *syntax*. This is why learning to think in algorithms is more valuable than memorizing any one language; once you can plan a solution clearly, translating it into code becomes the easy part.

## Key Concepts

- **Problem** — The task you're trying to solve, described in plain terms (e.g., "find the largest of three numbers").
- **Steps** — Individual instructions that, when followed in order, solve the problem. Each step must be clear and unambiguous — no guessing allowed.
- **Input** — The information an algorithm needs to start working (e.g., the three numbers you're comparing).
- **Output** — The result the algorithm produces after following all its steps (e.g., the largest number).
- **Finite** — A proper algorithm must eventually stop — it can't run forever. It should reach an answer in a limited number of steps.
- **Flowchart** — A visual diagram using boxes and arrows to represent an algorithm's steps and decisions, often used to plan logic before writing code.
- **Pseudocode** — Writing an algorithm in a code-like structure, but using plain English instead of a specific programming language's exact syntax — a useful middle step between plain language and real code.

Notice we solved the *entire logic* using only plain language and comparisons — no programming language needed yet. This is the real value of an algorithm: it works no matter what language you eventually use to write it.

**Step 2 — Now translate this exact plan into C code:**

```c
#include <stdio.h>

int main() {
    int a = 12, b = 45, c = 30;
    int largest;

    if (a > b) {
        largest = a;
    } else {
        largest = b;
    }

    if (c > largest) {
        largest = c;
    }

    printf("The largest number is %d\n", largest);

    return 0;
}
```

**Step 3 — Understand each line:**

- `int a = 12, b = 45, c = 30;` — Creates three variables holding our three numbers.
- `int largest;` — Creates an empty variable that will eventually hold whichever number turns out to be the biggest.
- `if (a > b) { largest = a; } else { largest = b; }` — This matches step 2 of our algorithm exactly: compare `a` and `b`, and store the bigger one in `largest`.
- `if (c > largest) { largest = c; }` — This matches step 3: compare `c` against whatever's currently in `largest`, and update it if `c` is bigger.
- `printf("The largest number is %d\n", largest);` — This matches step 4: display the final answer.

**Step 4 — Trace through it like the computer would:**

With `a = 12`, `b = 45`, `c = 30`: first, is `a > b`? Is 12 > 45? No — so `largest` becomes `b`, which is 45. Next, is `c > largest`? Is 30 > 45? No — so `largest` stays 45. The program prints:

Notice how the code follows the exact same steps we planned in plain English — that's the whole point of writing the algorithm first.
