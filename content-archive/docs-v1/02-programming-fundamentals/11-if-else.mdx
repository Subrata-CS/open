# If-Else

## Overview

Let's start from absolute zero, with no assumptions at all.

Every day, without even thinking about it, you make decisions based on conditions. "**If** it's raining, **then** I'll take an umbrella. **Otherwise**, I won't." "**If** I have enough money, **then** I'll buy the shirt. **Otherwise**, I'll wait." Notice the pattern: there's always a **question** (is it raining?), and depending on the **answer** (yes or no), you do one thing or a different thing.

**`if-else` is exactly this same pattern, written as code.** It's the single most important tool that lets a computer program "think" — letting it check something, and then choose what to do next based on the answer. Without `if-else`, a computer program can only ever do the exact same thing, every single time, no matter what. With `if-else`, a program can finally react differently depending on the situation — which is really what makes software feel "smart" or "responsive."

Let's build this up extremely slowly, one tiny piece at a time, so nothing feels confusing.

## A Quick Note Before We Start: Comments

You'll notice some lines in the code examples below that start with `//`. This is called a **comment** — anything written after `//` on a line is completely ignored by the computer. It doesn't run, it doesn't affect anything — it's purely a note left behind by the programmer, to explain what a piece of code is doing, for other people (or their future self) reading it later.

```c
// This entire line is a comment, and does nothing when the program runs
int age = 20; // You can also add a comment after real code, on the same line
```

## A Quick Note on Indentation

You'll also notice that code inside `{ }` is always pushed slightly to the right, using spaces or a tab. This is called **indentation**, and while C doesn't technically *require* it to work correctly, it's an extremely important habit — it visually shows you which lines "belong" to which `if` or `else` block, making code far easier to read and understand at a glance. Every proper programmer indents their code consistently.

## Step 1 — Understanding "Condition" (Before Any Code At All)

A **condition** is simply a question that has only one of two possible answers: **Yes** or **No** (in programming, we call this **True** or **False**).

Examples of conditions from real life:

- Is the door locked? → Yes or No
- Is your age 18 or more? → Yes or No
- Did you get more than 50 marks? → Yes or No

Notice: a condition is **never** "maybe" or "sometimes" — it's always a clean Yes/No answer. This matters a lot, because it's exactly how `if` works in code.

## Step 2 — What "if" Actually Means, in Plain Words

`if` simply means: **"Check something. If the answer is Yes, do the thing inside me. If the answer is No, skip me completely — as if I wasn't even there."**

That's it. That's the entire idea. Let's see this in the simplest possible C code:

```c
#include <stdio.h>

int main() {
    int age = 20;

    if (age >= 18) {
        printf("You are an adult.\n");
    }

    return 0;
}
```

**Let's read this extremely slowly, word by word:**

- `int age = 20;` — We're storing the number 20 in a box named `age`.
- `if (age >= 18)` — This is the **condition**, our "question." In plain English, it's asking: "Is the value inside `age` greater than or equal to 18?"
- `{` and `}` — These curly braces mark the **beginning and end** of what should happen if the answer is Yes. Think of them like a small fenced-off area: "everything inside this fence only happens if the condition was true."
- `printf("You are an adult.\n");` — This is the actual instruction that runs, but **only if** the condition above was true.

**What happens when this runs:** Since `age` is 20, and 20 is indeed greater than or equal to 18, the answer to our question is **Yes (true)**. So the line inside the curly braces runs, and we see:
```text
You are an adult.
```

**Now, what if `age` had been 15 instead?** The condition `15 >= 18` would be **No (false)**. In that case, the computer would completely skip everything inside the curly braces — as if that code didn't exist at all — and the program would print nothing and just end.

**Important rule:** Notice this example only used `if`, with no `else` at all. This is perfectly valid! You use a plain `if` (with no `else`) when you only care about doing something in the "Yes" case, and you're fine with the program simply doing nothing when the answer is "No." You only need `else` when you specifically want a *different* action to happen in the "No" case.

**Another important rule:** `else` can never exist by itself — it must always follow an `if`. Writing `else` alone, without a matching `if` right before it, is not valid code, and won't work.

## Step 3 — What "else" Adds to This

So far, our `if` only handles the "Yes" case. But what about when the answer is "No"? That's exactly what `else` is for.

`else` means: **"If the condition above was No, then do THIS instead."**

```c
#include <stdio.h>

int main() {
    int age = 15;

    if (age >= 18) {
        printf("You are an adult.\n");
    } else {
        printf("You are not an adult yet.\n");
    }

    return 0;
}
```

**Reading this slowly:**

- `if (age >= 18)` — Our same question as before: "Is age 18 or more?"
- Since `age` is 15, the answer is **No**.
- Because the answer was No, the computer completely skips the `if` block, and instead runs whatever is inside the `else` block.

**Output:**
```text
You are not an adult yet.
```

**The golden rule to remember:** In an `if-else` pair, **exactly one** of the two blocks will run — never both, and never neither. It's always either the `if` part OR the `else` part, based purely on whether the condition was true or false.

## Step 4 — Building the Condition: Comparison Operators

To ask a "Yes/No" question in code, we need special symbols called **comparison operators**. Here's every single one, explained in the simplest possible terms:

| Symbol | What It Asks (in plain English) | Example | Answer |
|---|---|---|---|
| `==` | "Are these two things exactly equal?" | `5 == 5` | Yes (true) |
| `!=` | "Are these two things NOT equal?" | `5 != 3` | Yes (true) |
| `>` | "Is the left side bigger?" | `10 > 3` | Yes (true) |
| `<` | "Is the left side smaller?" | `10 < 3` | No (false) |
| `>=` | "Is the left side bigger OR exactly equal?" | `18 >= 18` | Yes (true) |
| `<=` | "Is the left side smaller OR exactly equal?" | `10 <= 5` | No (false) |

**A very common beginner mistake:** People often accidentally write `age = 18` (single `=`) when they mean `age == 18` (double `==`). In C, a single `=` means "put this value into the box" (assignment), while double `==` means "check if these are equal" (comparison). Mixing these up is one of the most common bugs beginners run into — always double-check you're using `==` inside an `if` condition, not `=`.

## Step 5 — Asking More Than One Question at Once (&& and ||)

Sometimes, a single condition isn't enough — you need to check **two things at the same time**. For this, we use two special symbols:

- **`&&`** means **"AND"** — both questions must be Yes for the overall answer to be Yes.
- **`||`** means **"OR"** — at least one of the questions must be Yes for the overall answer to be Yes.

```c
#include <stdio.h>

int main() {
    int age = 20;
    int hasID = 1; // 1 means yes, they have an ID

    if (age >= 18 && hasID) {
        printf("You may enter the club.\n");
    } else {
        printf("Entry denied.\n");
    }

    return 0;
}
```

**Reading this in plain English:** "If the person is 18 or older, **AND** they have an ID, let them in." Both conditions must be true together — if either one is false (too young, OR no ID), the whole thing becomes false, and the `else` runs instead.

**Output:**
```text
You may enter the club.
```

## Step 6 — Very Important: Curly Braces `{ }` and Why They Matter

Every `if` and `else` block should have its instructions wrapped in curly braces `{ }`. Technically, C allows you to skip the braces if there's only **one single line** inside:

```c
if (age >= 18)
    printf("Adult\n");   // this works fine, without braces, since there's only 1 line
```

But this becomes dangerous the moment you add a second line later, forgetting to add braces:

```c
if (age >= 18)
    printf("Adult\n");
    printf("You can vote\n");  // WARNING: this line runs NO MATTER WHAT, even if age < 18!
```

Even though it *looks* like both lines belong to the `if`, only the very first line (`"Adult\n"`) is actually controlled by the condition. The second line is treated as a completely separate, unconditional instruction — a classic and very confusing beginner bug.

**The safe habit to build from day one:** Always use curly braces `{ }`, even for a single line:

```c
if (age >= 18) {
    printf("Adult\n");
    printf("You can vote\n");
}
```

Now both lines are clearly, safely grouped together, and both only run when the condition is true.

## Step 7 — What If We Have More Than Two Possibilities? (else if)

So far we've only handled two paths: Yes or No. But real life often has more than two options. For example: "If your score is 90 or above, you get an A. Otherwise, if it's 75 or above, you get a B. Otherwise, if it's 50 or above, you get a C. Otherwise, you get an F."

This needs **`else if`** — which lets us chain together multiple questions, one after another:

```c
#include <stdio.h>

int main() {
    int score = 82;

    if (score >= 90) {
        printf("Grade A\n");
    } else if (score >= 75) {
        printf("Grade B\n");
    } else if (score >= 50) {
        printf("Grade C\n");
    } else {
        printf("Grade F\n");
    }

    return 0;
}
```

## Step 8 — Nested if: Putting a Question Inside Another Question

Sometimes, one question naturally leads to another, more specific question. This is called **nesting** — literally, placing one `if` inside another `if`.

```c
#include <stdio.h>

int main() {
    int age = 20;
    int hasTicket = 1; // 1 means yes, they have a ticket

    if (age >= 18) {
        // We only reach this second question if the FIRST one was already true
        if (hasTicket) {
            printf("Welcome, enjoy the movie!\n");
        } else {
            printf("Please buy a ticket first.\n");
        }
    } else {
        printf("Sorry, you must be 18 or older to enter.\n");
    }

    return 0;
}
```

**Reading this like a story:** First, the program asks, "Is this person 18 or older?" Only if the answer is **Yes** does it even bother asking the second question, "Do they have a ticket?" If the person is under 18, it never even reaches the ticket question at all — it goes straight to the outer `else` and stops there.

**Output (with age=20, hasTicket=1):**
```text
Welcome, enjoy the movie!
```

This is exactly how you'd naturally think through the problem in real life too — you wouldn't ask "do they have a ticket?" before first confirming they're even old enough to be there at all.

## Step 9 — A Complete Walkthrough With a Real Problem

Let's put everything we've learned together, solving a small real problem completely from scratch: **"Tell the user if a number they enter is positive, negative, or zero."**

**Thinking it through in plain English first:**

1. Ask the user for a number.
2. If the number is greater than 0, it's positive.
3. Otherwise, if the number is less than 0, it's negative.
4. Otherwise (it must be exactly 0), it's zero.

**Now, the actual code:**

```c
#include <stdio.h>

int main() {
    int number;

    printf("Enter a number: ");
    scanf("%d", &number);

    if (number > 0) {
        printf("The number is positive.\n");
    } else if (number < 0) {
        printf("The number is negative.\n");
    } else {
        printf("The number is zero.\n");
    }

    return 0;
}
```

**Trying it with three different inputs, to see all three paths:**

- If the user enters `7`: `7 > 0` is true → Output: `The number is positive.`
- If the user enters `-4`: `-4 > 0` is false, but `-4 < 0` is true → Output: `The number is negative.`
- If the user enters `0`: both `0 > 0` and `0 < 0` are false → falls through to the final `else` → Output: `The number is zero.`

Notice how the `else` at the end doesn't need its own condition — by the time we reach it, we already know the number isn't positive and isn't negative, so it logically **must** be zero. This is the power of a well-structured `if / else if / else` chain: it covers every possible case, cleanly and completely.
