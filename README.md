## How it works

```
edit .md file  →  git push to main  →  GitHub Action builds  →  live in ~2 min
```

`sidebars.ts` has **no manual list** — it uses `type: 'autogenerated'`, so Docusaurus
scans the `docs/` folder and builds the whole sidebar itself.

| What you do | What happens on the site |
|---|---|
| Edit `docs/30-machine-learning/05-linear-regression.md` | That page updates |
| Add `docs/30-machine-learning/21-svm.md` | New page appears in the sidebar |
| Add folder `docs/41-something/` + `_category_.json` | New section appears |
| Delete a file | Page disappears, sidebar re-flows |

No config editing required.

## Local development

```bash
npm install
npm start          # http://localhost:3000/open/  (hot reload)
npm run build      # production build into ./build
npm run serve      # preview the production build
npm run typecheck  # TypeScript check
```

Node 20+ required.

## Writing a page

Every page is Markdown or MDX. Front matter controls title, sidebar label and URL:

```md
---
title: "Linear Regression"
sidebar_position: 5
sidebar_label: "Linear Regression"
slug: /machine-learning/linear-regression
description: "Linear Regression — Machine Learning | Open CS Hub"
---
```

Available out of the box:

- Syntax-highlighted code blocks with a copy button
- Admonitions — `:::tip`, `:::note`, `:::warning`, `:::danger`
- Mermaid diagrams — ` ```mermaid `
- Tabs, details/summary, tables, footnotes
- Offline full-text search (no API key, works on GitHub Pages)

## Adding React components to a page

Rename any `.md` to `.mdx` and import components directly — this is how live
calculators, graph visualizers, code runners and AI demos get added later:

```mdx
import MatrixCalculator from '@site/src/components/MatrixCalculator';

<MatrixCalculator size={3} />
```

Put the component in `src/components/`, write it in TypeScript, and it works on
every page that imports it.

## Bulk-scaffolding new topics

`tools/syllabus.txt` is the source of truth for the topic tree.

```bash
cd tools && python generate.py
```

Existing `.md` files are **never overwritten** — only missing files are created.
Section `index.md` pages and `_category_.json` are regenerated to keep the
sidebar in sync.

## Curated link pages

Four pages — **Practice**, **Resources**, **Global Career Links** and
**Projects** — are built from folders of Markdown lists, one file per group and
one line per link:

```bash
cd tools && python build_platforms.py   # platforms/  → Practice
cd tools && python build_resources.py   # resources/  → Resources
cd tools && python build_careers.py     # careers/    → Global Career Links
cd tools && python build_projects.py    # projects/   → Projects
```

`build_careers.py` refuses to list the same company twice, so separate lists
can be merged into `careers/` without a cleanup pass. On the site itself, the
**+** on any group opens that file in GitHub's editor — adding a company or a
project is one line, from a phone if you like. See `tools/README.md`.

## Deployment

`.github/workflows/deploy.yml` runs on every push to `main`, builds the site and
publishes it with the official GitHub Pages actions. In
**Settings → Pages**, Source must be set to **GitHub Actions**.
