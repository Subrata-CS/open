# Flowchart

## Overview

A **Flowchart** is a way of drawing an algorithm using shapes and arrows instead of just plain sentences. Every step of the algorithm becomes a box, and arrows show the order in which those steps happen — including which direction the program goes when it has to make a decision.

Remember our tea-making algorithm from earlier? We wrote it as a numbered list of steps. A flowchart takes that same list and turns it into a **picture** — a visual map you can follow with your eyes, moving from box to box along the arrows. Many people find it much easier to understand logic when they can *see* it laid out visually, especially when there are decisions involved (like "if this is true, go this way; if false, go that way").

Flowcharts are especially useful *before* writing any code, because they force you to think through every possible path your program could take — including what happens for both a "yes" and a "no" answer to any question — before you get lost in the details of actual programming syntax.

## Key Concepts

- **Start/End Shape (Oval)** — Marks where the flowchart begins and where it ends. Every flowchart has exactly one start and at least one end.
- **Process Shape (Rectangle)** — Represents a single action or instruction, like "add 5 to the total" or "store the result."
- **Decision Shape (Diamond)** — Represents a question with a Yes/No (or True/False) answer, splitting the flow into two different paths depending on the answer.
- **Input/Output Shape (Parallelogram)** — Represents getting information from the user (input) or showing information to the user (output).
- **Arrows (Flow Lines)** — Connect the shapes and show the exact order/direction the program follows, step by step.
- **Flow of Control** — The overall path the program takes as it moves through the flowchart, which can branch (at decisions) or loop back (during repetition).

Notice the **diamond shape** is where the flowchart splits into two separate paths — one for "Yes" and one for "No." Both paths eventually rejoin and lead to the same "End," but they print different messages along the way.

**Step 2 — Now translate this exact flowchart into C code:**

```c
#include <stdio.h>

int main() {
    int n;

    printf("Enter a number: ");
    scanf("%d", &n);

    if (n % 2 == 0) {
        printf("Even\n");
    } else {
        printf("Odd\n");
    }

    return 0;
}
```

**Step 3 — Match each line back to the flowchart:**

- `printf("Enter a number: "); scanf("%d", &n);` — This is the **parallelogram** (Input) — asking the user for a number and storing it in `n`.
- `if (n % 2 == 0) {` — This is the **diamond** (Decision) — checking the exact question from our flowchart.
- `printf("Even\n");` — This is the **rectangle** (Process) on the "Yes" path.
- `printf("Odd\n");` — This is the **rectangle** (Process) on the "No" path.
- The program naturally ends after either branch runs, matching the flowchart's single "End" oval.

This is exactly why flowcharts are so useful — every shape in the diagram maps directly onto a specific piece of real code, making it much easier to plan complex logic before you start typing.
